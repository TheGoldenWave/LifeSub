# 决策记录

本文件记录讨论中已经明确的方向。未列入的技术细节不视为已决定。

## D-001：软件先行

- 状态：已确认
- 决定：先验证软件记录与 Agent 记忆检索闭环，再开发可穿戴硬件。
- 原因：降低软硬件并行的不确定性，尽早验证核心用户价值。

## D-002：首个 Agent 能力是个人记忆检索

- 状态：已确认
- 决定：首版让 Agent 查询过去的对话、决定、时间和原文证据。
- 延后：实时上下文注入与录音控制。

## D-003：本地优先并支持 Provider 切换

- 状态：已确认
- 决定：本地 ASR 为默认路径，保留云端 ASR；摘要模型也可配置。
- 要求：记录实际模型、数据去向和处理时间。

## D-004：macOS 菜单栏应用

- 状态：已确认
- 决定：菜单栏负责快速录制与状态提示，本地管理页负责时间线、搜索、详情、权限和设置。

## D-005：macOS 会议内录为首个采集场景

- 状态：已确认
- 决定：分别采集系统音频与麦克风；保留文件导入入口。

## D-006：本地核心服务 + 薄客户端

- 状态：已确认
- 决定：LifeSub Core 统一实现处理、记忆、权限、检索、同步和审计；App 与插件只做适配。

## D-007：多宿主原生插件

- 状态：已确认
- 决定：首批支持 Codex 插件、DeepSeek Harness 原生插件和 Malow 插件，共享同一 Core API。

## D-008：按敏感级别返回 Agent 内容

- 状态：已确认
- 决定：普通内容可直接返回原文；敏感内容需要更严格授权。

## D-009：GitHub 分级同步

- 状态：已确认
- 决定：普通摘要可读，敏感记录加密，原始音频默认不上传。
- 边界：记忆数据使用独立私有仓库，不能写入公开代码仓库。

## D-010：本地 Codex 插件优先

- 状态：已确认
- 决定：首版 Codex 插件连接本机 LifeSub Core，通过本地或仓库插件市场分发。
- 延后：需要公网 MCP 与认证的公共 ChatGPT/Codex 插件。

## D-011：契约先独立，最终演进为 `lifesubd`

- 状态：已确认
- 决定：当前采用过渡方案 C，先抽出不依赖 Tauri 的 `CoreRuntime` 与版本化 Local Tool API；目标架构 A 是由独立常驻本地服务 `lifesubd` 托管同一 Core。
- 所有权：SQLite、录音状态、模型安装和 ASR Worker 只能由一个 Core 实例拥有。Tauri、DeepSeek Harness 与 ChatGPT Gateway 不得直接访问 SQLite、音频路径或模型目录。
- 接入：Tauri Command、本机 Unix socket 和未来 MCP Gateway 都是同一工具契约的适配器，不得复制业务逻辑。
- 生命周期：C 阶段退出 Tauri 进程仍会停止录音与处理；只有 A 阶段可承诺 UI 退出不影响后台任务。
- 安全：daemon 不直接监听公网或局域网；ChatGPT 开发者模式通过独立、认证的 Gateway 映射 MCP。

- 搜索与引用的精确工具契约。
- GitHub 加密与密钥恢复方案。
- Malow 插件接口。
- MVP 的量化质量与性能指标。
- 项目开源许可证。
