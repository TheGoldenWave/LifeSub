# LifeSub UI 走查与优化记录

日期：2026-09-02
范围：React 前端表现层，不含 Tauri、Rust、Swift、Catalog、服务接口与业务状态机。

## 走查结论

LifeSub 已建立清晰的深色 Evidence Terminal 方向，导航、录音、时间线、词典和设置均使用同一套基础色彩与字体。当前主要问题不是品牌方向，而是视觉系统在持续功能开发后出现密度、状态和响应式规则不完全一致。

## 2026-09-03 安装版截图复盘

用户提供的安装版截图暴露出第一轮浏览器验收没有覆盖的真实原生分支：`收音麦克风` 标签在录音头部被压缩后，文字越出自身网格单元并覆盖设备下拉框。该问题不是单个间距值偏小，而是头部 flex、可收缩 grid track 与 `white-space: nowrap` 共同造成的结构性碰撞。

本轮按真实产品分支重新检查 1180x760、1280x800、1516x1120、390x844，以及 125%/150% 缩放，并补充长设备名与已断开保存设备名。修复后标签、下拉框、刷新按钮、测试按钮和状态文字均保持独立边界；只有设备名称允许在下拉框内截断。

| 级别 | 最新发现 | 处理结果 | 后续建议 |
|---|---|---|---|
| P1 | 原生录音头部标签与下拉框重叠 | 已改为明确网格区域，标签不可收缩，窄屏独立成行 | 保留几何碰撞断言，所有原生专属控件必须进入视觉夹具 |
| P1 | 浏览器 Demo 截图没有渲染 Tauri 专属麦克风选择器 | 已增加 Tauri 运行时视觉夹具 | 后续原生专属设置、权限和设备状态都使用同类夹具验收 |
| P1 | 空闲录音页在头部、Ready 区和四行诊断中重复展示“待检测” | 已在稳定空闲态收起重复诊断，只在启动中或失败时展示详细事实 | 下一版本可进一步把 ASR 是否可用与开始按钮合并为单一结论 |
| P2 | 移动时间线在会话列表与统计之间产生大段空白 | 已让移动列表按内容高度收敛，统计紧随内容 | 可评估将统计折叠为一行摘要，减少首屏占用 |
| P2 | 移动词典详情仍显示新建/删除分类等无关管理操作 | 已在 entries/detail 状态隐藏顶部管理工具 | 详情操作继续保留在词条内容尾部，避免上下文切换 |
| P2 | 模型“暂不可安装”只给状态、不解释原因 | 已补充桌面运行时要求与下一步 | 后续对其他 `reason_code` 建立同样的用户语言映射 |
| P2 | 移动设置 Tab 较密，焦点与选中态可能同时抢眼 | 本轮保留现有可滚动结构 | 建议下一版缩短标签为“录音 / ASR / 模型 / 诊断 / 关于”，并让 focus ring 只表达键盘位置 |
| P2 | 桌面词典仍偏 CRUD 管理面，模型页内容少时空面过大 | 未在本轮扩展产品结构 | 建议按高频任务重新排序，不增加装饰卡片；需要产品确认后实施 |

### 为什么旧验收漏掉

- `LiveCapture` 只在 Tauri 运行时和麦克风必需模式下渲染选择器，浏览器 Demo 截图测试的是不同界面分支。
- JSDOM 组件测试只能确认语义与行为，无法测量文字和相邻控件的真实绘制边界。
- `scrollWidth <= clientWidth` 只能发现页面横向溢出，无法发现兄弟控件互相覆盖。
- 自动样式扫描没有文字 Range 与控件矩形信息，因此对这一类问题会产生假阴性。

### 新增验收护栏

- 使用浏览器内 Tauri IPC 夹具渲染真实麦克风选择器，不再以 Demo 分支替代安装版。
- 使用 label 文本 Range 与 select、刷新、测试按钮的 bounding box 做不相交断言。
- 覆盖 1180/1280/1516 桌面宽度、390 移动宽度、125%/150% 缩放、长设备名和已断开名称。
- 继续保留文档横向溢出检查，但不再把它当作无控件碰撞的充分证据。

## 2026-09-03 时间线滚动回归复盘

真实安装版在会话、Segment 和 revision 数量较多时，时间线内容将应用外层网格向下撑高。由于桌面 `body` 同时禁止滚动，侧栏底部的“设置”入口被推到视口之外，左右内容区也失去独立滚动边界。

根因是 `.app-shell`、`.sidebar`、`.workspace` 只有 `min-height: 100vh`，没有形成从根节点到时间线的确定高度链；子元素的 `height: 100%` 因此按内容增长而不是按窗口收敛。

修复后桌面端根节点、Shell、Sidebar 和 Workspace 固定在 `100dvh`，外层不滚动；Session Tree 与 Transcript 保留各自的 `overflow: auto`。移动端继续使用自然页面滚动，不套用桌面约束。

新增长数据验收会动态扩充会话和转写节点，并验证：应用与文档高度不超过 viewport、设置入口完整可见、左右区域均存在实际滚动距离、修改 `scrollTop` 能产生位移，并且设置弹层仍可打开。

| 级别 | 问题 | 用户影响 | 解决方案 |
|---|---|---|---|
| P1 | 部分交互控件缺少统一的 focus、disabled、loading 状态 | 键盘用户难以确认当前位置，异步操作状态不稳定 | 建立共享控件状态和 2px `focus-visible` 规则，稳定控件尺寸 |
| P1 | 窄屏下三栏页面、工具栏和设置弹层存在拥挤风险 | 长设备名、Evidence URI、工具按钮可能挤压或溢出 | 按 1024/768/520px 进行结构切换，允许元数据换行并保持关键操作可见 |
| P1 | 录音状态、权限/设备状态与错误提示的视觉层级接近 | 用户在时间压力下难以快速判断是否正在可靠录音 | 将状态区、动作区和恢复提示分层，颜色只表达状态并同时保留文字 |
| P2 | 时间线左栏、Transcript 工具区和正文层级接近 | 扫描记录、revision 和原文时认知负担偏高 | 固定导航/列表宽度，强化当前记录与 revision，限制正文行长 |
| P2 | 设置、诊断、模型页面的行高、分区和反馈样式不统一 | 信息密集页面难以横向比较和定位异常 | 统一设置分区、字段行、状态标签、反馈区和工具栏结构 |
| P2 | 词典三栏在中小窗口下缺少渐进式重排 | 分类、词条与详情互相挤压 | 大屏三栏、中屏双栏、窄屏单列堆叠，并保持搜索和新建操作可访问 |
| P2 | CSS 中存在重复规则和零散尺寸值 | 后续功能容易继续产生视觉漂移 | 补充语义 token，并将控件、面板、动效和内容尺寸统一引用 token |
| P3 | 空状态留白和辅助文字灰度偏弱 | 空页面显得松散，辅助信息阅读吃力 | 收紧空状态宽度与节奏，保持 WCAG AA 对比度和明确下一步操作 |

## 保留项

- 保留蓝灰近黑画布、扁平表面、锐角边界和无阴影视觉语言。
- 保留等宽字体承载状态、时间、来源、revision 和 Evidence URI。
- 保留比例字体承载中文转写正文。
- 保留录音、暂停、成功、错误和焦点作为仅有的功能色用途。
- 不隐藏 provenance、revision、Provider、设备与权限事实。

## 二次体验走查：当前仍然不好用或不好看的地方

本节基于优化后的桌面与 390px 窄屏截图，以及录音、时间线、Transcript、词典、设置、模型和诊断组件的实际交互重新评估。以下内容不是本轮已修问题的重复记录，而是当前界面虽然已经满足基础可用性，仍会让用户觉得费力、粗糙或不够像成熟桌面工具的部分。

变更类型说明：

- **V（纯视觉）**：可继续限定在 Token、CSS、布局和展示文案，不改变业务行为。
- **I（前端交互）**：需要调整 React 组件交互，但不需要新增后端接口或改变数据契约。
- **P（产品行为）**：需要在下个版本单独确认产品规则，即使实现仍可能只发生在前端。

| 优先级 | 区域 | 当前问题 | 为什么不好用 / 不好看 | 优化建议 | 类型 |
|---|---|---|---|---|---|
| P1 | 移动端录音 | 录音控制位于页面顶部，实时转写和笔记变长后，暂停、继续和停止会滚出视野 | 录音是高风险、强时效操作，用户不应为了停止录音向上寻找按钮 | 窄屏录制期间增加固定底部控制条，只保留暂停/继续、停止和当前时长；顶部继续展示完整设备与状态事实 | I |
| P1 | 移动端时间线 | Session Tree 与 Transcript 纵向完整堆叠；选择会话后详情仍在列表下方 | 会话较多时，用户需要跨越很长列表才能看到刚选中的内容，主从关系在窄屏失效 | 768px 以下切换为“会话列表 / 记录详情”两级视图，选择后进入详情，并提供明确返回列表入口；保留搜索上下文 | I |
| P1 | 移动端词典 | 分类、词条、详情依次纵向铺开，点击词条后详情可能远在屏幕下方 | 用户已完成选择却看不到结果，容易误以为点击无效；编辑流程需要反复长距离滚动 | 改为“分类 → 词条 → 详情/编辑”的窄屏钻取流程，顶部保留范围与返回路径；保存后回到词条详情并保持原滚动位置 | I |
| P1 | 设置 | 设置修改后没有“已修改”提示，保存按钮也不区分原值与脏值；直接关闭弹层会静默丢弃编辑 | 用户无法判断是否需要保存，也无法确认关闭是否会丢失配置 | 前端维护初始快照与 dirty 状态：无改动时禁用保存，有改动时显示“有未保存更改”，关闭时提供放弃/继续编辑选择 | I / P |
| P1 | 时间线列表 | 点击会话标题同时执行“选中”和“展开/收起” | 两个不同意图绑定到同一点击区，重复查看当前会话时会意外折叠内容 | 将箭头设为独立展开控件；标题区域只负责选择会话，并补齐 `aria-expanded` 与键盘左右键行为 | I |
| P1 | 删除与重命名 | 词典删除、声纹重命名/删除仍使用 `window.confirm` / `window.prompt`，且危险操作与普通文字按钮外观接近 | 系统弹窗割裂视觉语言、信息不足；“删除分类”未在界面上提前说明影响词条数量，误操作成本高 | 使用项目内统一确认弹层或行内编辑；删除前展示对象名称、关联数量和不可逆结果，危险操作使用一致的 danger 样式 | I |
| P2 | 录音桌面空闲态 | 主内容区存在大面积无信息留白，状态说明在顶部、主操作在最右侧、空状态又在中央重复表达“未开始” | 视觉重心散开，第一眼更像空白调试面板，而不是准备就绪的录音工具 | 将“设备是否就绪、捕获模式、ASR 模型、预计写入位置”收束为紧凑的就绪区，让开始操作与状态相邻；减少重复空状态文案 | V / I |

| P2 | Transcript 播放 | 播放入口只在每条时间戳上，播放状态是正文顶部的一行文本，没有持续可见的播放控制 | 用户滚动阅读后无法快速暂停、继续或确认当前片段，长记录中尤其低效 | 增加贴底或贴顶的轻量播放条，显示来源、当前时间/片段终点、播放/暂停；点击 Session Tree 片段时同步定位并播放对应片段 | I |
| P2 | 时间线搜索 | 搜索会过滤记录和片段，但没有结果数量、命中位置概览或清除入口 | 用户不知道是命中 1 条还是 20 条，也难以在多个命中之间移动 | 搜索框内增加清除按钮与结果计数；Transcript 提供上一处/下一处命中，Session Tree 保留命中上下文而不是只留下孤立片段 | I |
| P2 | 模型管理 | “未安装”和“暂不可安装”并列成两个相似标签；下载阶段、安装状态和可执行动作挤在同一行 | 状态与按钮长得太像，用户要逐字阅读才能判断能不能操作；失败时直接展示 `network_interrupted` 也显得像工程日志 | 每个模型只保留一个主状态和一个主动作；进度占独立整行；错误先给可读原因与恢复动作，原始错误码作为可展开技术详情保留 | V / I |

| P2 | 词典桌面 | 三栏都以硬边界等权切开，中间词条很少时出现巨大空洞，右侧长期展示大段“词典说明” | 页面结构清楚但视觉僵硬，像数据库管理器；空白面积与信息价值不匹配 | 分类栏保持紧凑，词条区成为主要工作面；无选中项时将说明压缩成短提示，不长期占据完整第三栏；详情出现时再展开编辑区 | V / I |

| P3 | 全局视觉 | `DICTIONARY`、`MODELS`、`DIAGNOSTICS`、`EVIDENCE RECORD` 等小号全大写英文 eyebrow 在多个页面重复 | 与中文界面形成模板化装饰，增加噪声而没有增加信息；这是当前最明显的“像设计模板”痕迹 | 只在 Evidence URI、revision、Provider identity 等真正技术元数据中使用等宽英文；页面标题直接使用中文，不再重复英文眉题 | V |
| P3 | 全局视觉 | 大量 1px 边框、近似深灰表面和矩形框同时存在，几乎所有区域都靠框线分组 | 虽然遵守无阴影方向，但层级过度依赖边框，界面显得硬、平、密，重点不突出 | 删除不承担交互或分组含义的外框；使用表面明度、间距和标题对齐建立层级，只为可点击控件、数据边界和关键状态保留边框 | V |
| P3 | 字体 | 小号等宽字体被用于大量说明、标签和状态，移动端阅读负担明显 | 等宽字体适合证据与身份，不适合连续中文说明；过多使用会让产品像日志查看器 | 正文、说明、空状态统一使用比例字体和舒适行高；等宽字体仅保留给时间、URI、hash、revision、Provider 与状态码 | V |

## 视觉完成度判断

当前页面的成熟度并不平均：

| 页面 | 当前判断 | 最明显的短板 |
|---|---|---|
| 时间线桌面版 | 当前最成熟，信息结构和 Evidence 层级已经成立 | 列表选择/展开冲突，播放与搜索效率仍不足 |
| 录音页 | 状态语义已比优化前可靠，但空闲态仍显得空和散 | 主操作、设备就绪事实、实时内容没有形成一个稳定视觉中心 |
| 词典页 | 功能完整，但当前最像后台 CRUD 页面 | 三栏等权、框线过多、移动端选择后看不到详情 |
| 设置页 | 一致性已有改善，但仍像“配置字段集合” | 缺少 dirty 状态、异常导航和清晰的保存闭环 |
| 模型页 | 当前最粗糙的状态型页面 | 状态、动作、进度和错误码混排，按钮与标签难区分 |
| 诊断页 | 事实最完整，但结论最不直观 | 用户必须自己从多行技术事实推导是否可录音，长身份信息不可直接使用 |

从纯审美角度看，优先需要处理的三处是：

1. **录音空闲页的大面积死空和分散重心**：不是留白，而是缺少就绪信息形成的内容真空。
2. **词典的三等分后台布局**：结构正确但比例僵硬，空白和边框比词条本身更抢眼。
3. **模型管理的“双状态标签 + 动作”混排**：看起来像内部工具，用户需要理解实现状态后才能决定下一步。

## 建议的下一轮优化顺序

### 第一阶段：不改业务行为的视觉收口

- 去除重复英文 eyebrow，收敛等宽字体使用范围。
- 减少无意义外框，重新建立页面标题、分区标题、正文和技术元数据的层级。
- 重做录音空闲态、词典空详情态、模型状态行和诊断摘要的版式。
- 统一危险操作、状态标签、错误摘要和成功反馈的视觉表达。

### 第二阶段：纯前端交互效率

- 增加移动端录音固定控制条。
- 将移动端时间线和词典改为主从钻取，而不是整页纵向堆叠。
- 拆分 Session Tree 的选择与展开行为。
- 为搜索补充清除、数量和命中导航，为播放补充持续可见控制条。
- 为设置增加 dirty 状态、关闭保护和完整 tab 键盘交互。

### 第三阶段：需要产品确认的体验规则

- 是否保留底部统计栏，还是将统计移到独立入口。
- 浏览器演示模式是否继续模拟录音，或明确定位为只读示例数据。
- 删除分类时如何处理分类内词条，以及需要何种撤销/恢复策略。
- 设置关闭时采用强制确认、自动保存草稿，还是显式放弃修改。

建议下一版本先完成第一阶段与第二阶段中的前三项。它们不要求改变后端接口，却能直接解决当前最明显的“像工程面板”和移动端操作成本问题。

## 2026-09-03 实施结果

本轮已完成走查中不需要新增后端接口或改变产品数据规则的视觉与前端交互优化：

- 录音页将开始操作与就绪事实收束到同一区域；移动录制/暂停期间固定显示当前时长、暂停/继续和停止操作。
- 浏览器环境只保留一处完整免责声明，页面内统一使用“示例转写”任务文案；错误状态不再在标题、副标题和通知中重复。
- Timeline 在窄屏改为会话列表与记录详情两级视图；Session Tree 的展开和选择拆分，并支持左右键展开/收起。
- 搜索支持正文、来源和时间，提供清除、会话/命中计数、上一处/下一处；片段可定位到 Transcript，并在音频可用时播放。
- Transcript 增加持续可见的播放控制，切换记录或 revision 会清理旧播放状态。
- 词典在窄屏改为分类、词条、详情三级钻取；桌面空详情收起；分类和词条删除改为带对象与影响说明的页内确认，并防止重复提交。
- 设置增加 dirty 标记、草稿保留、关闭保护和无改动时禁用保存；声纹重命名/删除与实时说话人命名均改为产品内行内交互。
- 模型页只显示一个主状态，进度、动作、友好错误摘要和技术详情分层。
- 诊断页增加保守摘要，完整保留并支持复制设备 UID、路径、应用/helper/runtime hash、模型 bundle identity 与 runtime identity。
- 移除重复英文眉题，减少不承担分组含义的边框，并将等宽字体收敛到 Evidence、时间、revision、Provider、hash 和错误码等技术事实。
