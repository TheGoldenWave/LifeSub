## Task 7 And Task 8 Result

- Catalog v6 records capture sources and timing without rewriting immutable v5 evidence.
- Chunk sealing validates anchored paths, file identity, size, SHA-256, source and timing before publication.
- Durable seal intent and startup reconciliation cover rename/crash windows, stale temp files and native orphans.
- The Swift helper consumes strict start/pause/resume/stop/shutdown commands and drives AVAudioEngine microphone plus ScreenCaptureKit system audio.
- Rust coordinates a source set atomically, registers real helper metadata, drains sealed chunks and commits them to the Catalog.
- Capture timing uses a common continuous-nanosecond domain with cumulative per-source sample ranges.
- Desktop production selects `NativeCaptureRuntimeFactory`; the release gate now accepts native capture capability.
- The anchored SQLite VFS read-only regression was fixed by restoring `SQLITE_OPEN_READWRITE` after a verified `O_RDWR` descriptor open.

Native capture is still missing target-machine permission, device, packaged-helper, crash/restart and long-run evidence. Production wiring is not equivalent to hardware acceptance.

## Task 9 Result

The current desktop Worker constructs `ProductionNativeAsrEngine`. Its execution path now covers:

- ownership-safe lookup of an exact executable installation lease;
- exact `model_id`, manifest version and bundle identity matching against the execution snapshot;
- anchored, no-follow audio open with hash and byte-length revalidation;
- working-audio decode/resample and bounded inference windows;
- provider selection copied from the frozen snapshot;
- cancellation-aware background execution and renewal callbacks;
- validated provider receipt and chunk-bound segment construction;
- existing JobCoordinator fencing for publication.

The `NativeAsrDesktopRuntimeFactory` capability marker is intentionally absent. Do not add it from compilation evidence alone.

## Release Blockers

1. The canonical LifeSub ModelManager has not installed and qualified a supported model; `model_installations` is empty.
2. There is no exact execution lease or packaged real-audio inference evidence for the current engine.
3. Receipt, revision, segments, search, playback, retry and retranscription have not been verified end to end with real model output.
4. Task 10 persisted UI event behavior is not complete.
5. Task 11 hardware scenarios and the 30-minute run are not complete.
6. Tier 2/Tier 3, nested signing, DMG validation and installed-app acceptance remain outstanding.

Other applications' ONNX files are not LifeSub model evidence and must not be imported directly into the release proof.
