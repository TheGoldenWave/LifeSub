## 结论

当前版本可以作为交互原型演示，但不具备真实录音、ASR 与证据归档产品的交付条件。最大风险不是单个按钮失效，而是 Demo 数据和 Mock 结果被呈现为真实能力，可能造成错误证据与“已保存”错觉。

问题分级：Critical 2 项，Important 11 项，Medium 17 项，Minor 5 项，共 35 项。

证据标记：

- **实机确认**：已通过安装包操作验证。
- **截图确认**：可从用户截图直接确认。
- **代码确认**：已从对应源码确认。
- **待补测**：已有强指向证据，需在目标安装包中补充验证。

## Critical

### C1 Mock 台词被呈现为真实 SenseVoice 实时转写

- 证据：实机确认、代码确认
- 位置：`src-tauri/src/capture/streaming.rs:126`、`src/components/LiveCapture.tsx:181`
- 点击开始记录后，无论现场声音如何，都会按固定顺序展示预置台词；后端固定使用 `MockStreamingSource`。
- 界面却显示“实时 SenseVoice”“正在记录”等正式能力文案。
- 影响：用户会误判麦克风、系统音频、声纹识别与 ASR 已工作，并可能把伪造内容当作证据。
- 修复：生产构建禁止默认 Mock；Demo 必须显式开启并持续显示“演示数据，不会录音”；真实采集或 ASR 启动失败必须进入失败态。

### C2 “录音已保存”与真实时间线记录不一致

- 证据：实机确认、代码确认
- 位置：`src/components/LiveCapture.tsx:92`、`src/App.tsx:14`、`src/App.tsx:43`
- 停止后提示“录音已保存”，但时间线始终由 `demoRecords` 初始化；LiveCapture 没有返回新记录或完成真实 Catalog session 封存。
- 影响：用户关闭应用后可能发现录音无法恢复，属于核心数据丢失风险。
- 修复：只有真实 session、音频 chunk、segment 和 Catalog 事务成功后，才能显示保存成功；失败时提供恢复与重试入口。

## Important

### I1 停止后无法开始第二次记录

- 证据：实机确认、代码确认；位置：`src/components/LiveCapture.tsx:188`
- `stopped` 状态没有新记录动作，核心流程无法循环使用。
- 修复：支持 `stopped -> idle -> recording`，或直接显示“开始新记录”。

### I2 `⌘R` 快捷键提示无效

- 证据：实机确认；位置：`src/components/LiveCapture.tsx:253`
- 页面宣称按 `⌘R` 可启动实时转写，但没有键盘监听或菜单级快捷键。
- 修复：实现并测试快捷键，或删除该提示。

### I3 两个“导入音频”入口都无法完成导入

- 证据：实机确认、代码确认；位置：`src/App.tsx:24`、`src/components/TimelineView.tsx:45`
- 侧栏入口只提示功能将在时间线可用；时间线入口也没有完成文件选择、复制、hash、任务和记录创建。
- 修复：统一接入 Tauri dialog、`import_audio_file`、hash、Catalog、ASR Job、进度和错误态。

### I4 时间线、搜索和统计使用固定 Demo 数据

- 证据：实机确认、代码确认；位置：`src/App.tsx:14`、`src/components/TimelineView.tsx:67`
- 记录来自 `demoRecords`，统计来自 `demoStats`，真实 `loadStats()` 未执行。
- 修复：桌面模式从 Catalog 加载；Demo 数据仅限显式浏览器演示模式，并明确展示 Demo 标识。

### I5 时间戳播放按钮没有处理逻辑

- 证据：实机确认、代码确认；位置：`src/components/TranscriptView.tsx:55`
- 点击“播放 00:12”等按钮无状态变化，按钮没有 `onClick`、音频资源或进度控制。
- 修复：绑定音频、起点跳转、播放/暂停、当前进度及缺失音频错误态。

### I6 修订只修改前端内存

- 证据：实机确认、代码确认；位置：`src/components/TimelineView.tsx:24`
- 保存后界面显示新 revision，但没有稳定写入 Catalog，重启后丢失。
- 修复：调用 `append_transcript_revision`，成功后刷新记录；失败时保留草稿并允许重试。

### I7 历史 revision 查看会覆盖当前 revision

- 证据：代码确认；位置：`src/components/TranscriptView.tsx:49`、`src/App.tsx:22`
- “查看原始 r1”直接替换当前 revision，不是只读查看；可能造成编号和 Catalog 状态不一致，也没有可靠返回最新版本入口。
- 修复：使用只读 revision 查看器或版本选择器，查看历史版本不得创建或覆盖当前 revision。

### I8 AI 润色失败时静默降级为字符串替换

- 证据：实机确认、代码确认；位置：`src-tauri/src/llm/polish.rs:62`、`src/components/LiveCapture.tsx:107`
- Ollama 不可用时执行 `mock_polish`，前端仍提示“润色完成”。
- 修复：返回 Provider、Model、fallback 和错误；正式模式禁止静默 Mock，明确区分规则清理、LLM 润色和失败。

### I9 设置弹窗正文被压成窄条

- 证据：截图确认、实机确认、代码确认；位置：`src/styles.css:197`、`src/styles.css:395`、`src/components/Modal.tsx:14`

- 修复：Modal body 改为单列，设置内容内部再使用布局；补充默认、窄窗口和放大字体验收。

### I10 设置弹窗焦点泄漏到背景页面

- 证据：实机确认
- 打开设置后按 Tab，焦点会进入被遮挡的“开始记录”按钮。
- 修复：使用语义化 dialog、初始焦点、焦点循环、背景 `inert` 和关闭后的焦点恢复。

### I11 模型、声纹和词典存在多组无逻辑按钮

## Medium：截图确认的 UI 与信息架构问题

### M13 纯图标按钮缺少可见语义

### M16 中文文本过度使用等宽字体

- 证据：截图确认，全部截图

## 已确认可用、应保留

- 侧栏导航、会话切换和前端搜索可用。
- 暂停/继续可以暂停 Mock 事件流，状态反馈清晰。
- Evidence URI 与全文复制可以写入系统剪贴板。
- Markdown 可以导出到下载目录，frontmatter 结构基本正常。
- ASR、录音设置具备 Catalog 读写接口，重新打开设置可读取已保存值。
- 深色、扁平、锐利边界和等宽操作层符合既定设计方向。

以上能力的交互可用性不等于真实数据闭环可用；例如 Markdown 导出可用，但当前内容仍可能来自 Demo 数据。

## 修复顺序

1. 禁止生产路径使用 Mock，移除未经 Catalog 成功确认的“已保存”提示。
2. 打通真实录音、音频 chunk、session、segment、Catalog 和时间线恢复。
3. 修复设置弹窗布局、焦点管理、二次录音、快捷键、导入、播放和 revision 持久化。
4. 接通模型、声纹、词典和 AI 润色的真实逻辑，补齐加载、错误、取消、重试和回滚。
5. 修复时间线布局、标签换行、重复导入入口、对比度、字体和边框层级。
6. 以独有测试口令完成安装包级真实音频验收，并验证退出重启后的检索、播放和导出；验收数据不得来自 Demo/Mock。
