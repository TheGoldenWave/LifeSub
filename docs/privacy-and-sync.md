# 隐私、权限与 GitHub 同步

## 基本原则

- 本地优先：原始音频、主数据库和搜索索引默认留在用户设备。
- 明确外发：任何云端 ASR、摘要或同步都要显示数据去向。
- 最小披露：Agent 只获得完成当前请求所需的内容。
- 可追溯：每次模型处理和 Agent 原文访问都进入审计日志。
- 用户控制：用户可以调整敏感级别、撤销访问和触发删除。

## 已确认的 Agent 访问策略

采用“按敏感级别决定返回范围”：

- 普通内容：搜索结果可以直接包含相关原文与时间戳。
- 敏感内容：默认返回摘要或受限提示，读取原文需要更严格的授权。

敏感级别数量、默认分类规则、授权交互和授权有效期仍待正式设计。自动分类只能提供建议，不能成为不可解释的最终权限决定。

## GitHub 的角色

GitHub 是同步、版本和灾备中心，不是实时数据库，也不是原始音频存储中心。

建议同步内容：

- 普通记忆：可读 Markdown 或结构化 JSON。
- 敏感记忆：客户端加密后的文件。
- 原始音频：默认不同步，只保存本地引用与校验值。
- 数据库和向量索引：默认不同步，可从记忆文件重建。

## 仓库隔离

当前 `TheGoldenWave/LifeSub` 是公开代码仓库。真实个人数据必须使用用户单独创建的私有记忆仓库，例如 `lifesub-vault`。LifeSub 应在配置时阻止或强提醒用户不要把记忆同步到公开仓库。

## 建议的记忆库结构（草案）

```text
lifesub-vault/
├── memories/
│   └── YYYY/MM/<memory-id>.md
├── private/
│   └── YYYY/MM/<memory-id>.age
├── manifests/
│   └── devices.json
└── vault.json
```

加密算法、密钥保存、设备授权和恢复流程尚待设计。密钥不得提交到 GitHub。

## Git 的限制

- Git 不适合大音频与高频写入。
- 多设备同时修改可能产生冲突。
- 从当前分支删除文件不等于从 Git 历史彻底删除。
- 私有仓库降低暴露面，但不能替代客户端加密。
- 同步需要批处理、稳定文件命名和确定性序列化，避免无意义冲突。

## 合规与伦理

- 录音状态需要明确可见，后续硬件也应有灯光、声音或振动提示。
- 会议和谈话录音应支持同意提示与快速暂停。
- 不同地区对单方或双方同意的要求不同，产品不能默认“个人使用即合法”。
- 用户应能配置保留期限、自动删除和禁止同步范围。
- 商用前需要针对中国大陆、GDPR 及美国各州法律进行专项审查。
