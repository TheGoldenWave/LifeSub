# LifeSub Evidence 基础设施：开放问题与验证议程

状态：待验证研究议程，不是 V0.2.1 实现范围

日期：2026-08-25

来源：2026-08-24 三段个人 AI 产品沟通 ASR，以及 LifeSub 当前长时音频与 ASR Evidence 定位

## 0. 当前护栏

本文不能用于提前扩张当前开发范围。当前唯一优先级仍是完成 Catalog v6、atomic chunk sealing、production NativeCaptureCoordinator、native ASR executor 和真实安装包验收。

以下问题只有在当前 Evidence Core 真实闭环通过后，才能进入 PRD 或实现。讨论全天候、跨设备和硬件时，必须明确它们是长期愿景，而不是已交付能力。

## Q-L1：音频是否已经覆盖个人环境信息价值的 80%？

### 问题定义

对话提出：相比视觉和专用硬件，音频可能已经覆盖会议、交流、灵感和大量日常信息。该判断若成立，LifeSub 可以长期坚持窄 Evidence 定位；若不成立，才需要更早研究视觉或传感器。

### 暂定假设

对于第一批知识工作者，用户显式启动的会议、讨论和语音记录能覆盖最有价值、最容易形成 Project Evidence 的场景；视觉是补充，不是首版前提。

### 最小实验

- 连续 4 周记录本人真实会议、讨论和灵感；
- 每周回顾哪些重要事实、决定和行动无法仅靠音频还原；
- 对缺口分类：必须视觉、需要文档附件、需要传感器、只是 ASR/说话人质量不足；
- 统计音频独立覆盖率和补充证据类型。

### 通过信号

绝大多数高价值记录可以通过音频、时间戳、附件引用和人工笔记可靠还原，不需要持续视觉采集。

### 停止条件

如果关键场景普遍需要屏幕、物体、位置或身体指标才能理解，则把它们定义为外部 Evidence source，而不是让 LifeSub 直接吞下所有传感器。

## Q-L2：何时从“显式长时录音”升级到“全天候环境采集”？

### 问题定义

全天候采集可以降低遗漏，但会显著增加隐私、同意、续航、噪声、存储和社会接受度风险。技术可行不等于产品应该默认开启。

### 升级 Gate 候选

只有同时满足以下条件才研究自动采集：

- 显式长时录音已稳定、可恢复、可删除；
- 用户真实数据证明存在持续遗漏且价值显著；
- 可以用场景、日程、设备状态或物理动作做可解释触发；
- 录音状态始终可见，支持一键暂停和硬件级反馈；
- 他人同意、敏感场所和保留期限有明确策略；
- 噪声筛选不会静默生成正式知识。

### 最小实验

先做“建议开始录音”而非“自动录音”：根据会议日程或当前应用提示用户，记录接受率、遗漏改善和打扰感。未验证前不后台自动开启麦克风。

## Q-L3：跨设备 Evidence 如何合并而不制造重复和时间线错误？

### 问题定义

手机、耳机、手表和电脑可能同时捕获同一事件。跨设备不是简单上传，需要解决时钟偏差、重叠音频、设备身份、声道质量、离线封存、授权和冲突。

### 暂定原则

- 每个设备独立产生不可变 Chunk 和设备签名；
- Catalog 合并元数据和关系，不覆盖原件；
- 重叠记录可以建立 `same_event` / `overlaps` 关系，不自动删除；
- 时间校准和去重结果是可重建派生数据；
- 下游引用精确 Evidence Ref，不引用“自动合并后的模糊记录”。

### 最小实验

在 Mac + 手机双设备录制同一 30 分钟会议，模拟时钟偏差、断网、提前停止和重复上传，验证事件聚合、播放和撤回语义。

## Q-L4：LifeSub 应保存一切，还是主动筛选“有价值 Evidence”？

### 问题定义

Evidence 系统需要忠实保存原件，但长期录音会制造大量低价值内容。若 LifeSub 主动判断价值，就会越界进入 Malow 的解释或 GoldenWave 的治理；若完全不筛选，用户会面对存储和检索负担。

### 暂定分层

- LifeSub 可以根据静音、质量、完整性和用户显式标记做技术筛选；
- Session Digest、主题和重要性只能是可删除的导航派生物；
- Project 意义、决定、行动项由 Malow Review 产生；
- 长期事实和知识由 GoldenWave Govern 决定；
- 自动过期和删除必须由可解释 retention policy 控制，不能由模型单独决定。

### 最小实验

对 50 个真实 Session 比较关键词检索、导航 Digest 和 Malow Organizer 三种找回方式，评估找回率、误导率和用户时间。

## Q-L5：Evidence 进入 Malow 或 GoldenWave 前需要什么人工确认？

### 问题定义

项目型记录适合由 Malow 结合 Project / Matter 解释；健康、生活和私人反思可能不需要 Project，但仍不能让 LifeSub 自动写正式 Memory。

### 待验证路径

```text
项目型：LifeSub → Malow Organizer → Human Review → GoldenWave
非项目型：LifeSub → independent Human Review → GoldenWave
无长期价值：保留或按策略删除，不进入 GoldenWave
```

### 最小实验

选取项目会议、私人反思、健康沟通各 10 条，比较统一 Review 与分场景 Review 的时间、误分类、敏感数据暴露和 Candidate 接受率。

## Q-L6：第一人称视觉什么时候值得引入？

### 问题定义

眼镜能提供与人视角一致的视觉 Evidence，但续航、隐私、场所规范和社会接受度成本远高于音频。

### 引入 Gate

- Q-L1 证明存在高频、关键、音频无法补足的视觉缺口；
- 可以使用低频、事件触发的图像，而非默认连续录像；
- 图像状态、同意和删除有比音频更严格的控制；
- 视觉 Evidence Contract 与音频使用同一来源、hash、授权和撤回原则；
- 不因多模态模型可用就提前扩张产品。

## Q-L7：什么时候值得做专用硬件？

### 问题定义

专用硬件可改善续航、收音和物理提示，也会增加供应链、认证、售后和生态锁定。当前策略是软件先行，复用已有设备。

### 硬件立项条件候选

- 手机/电脑/现有录音设备无法满足核心采集场景；
- 已有用户持续使用软件并明确提出同一硬件痛点；
- 可量化的续航、收音或操作提升足以抵消携带成本；
- 物理录音提示、静音和本地加密形成明确可信优势；
- 软件 Evidence Core 和 Contract 已稳定，硬件只是 producer。

### 停止条件

若现有设备加软件能覆盖主要场景，LifeSub 不自研硬件，只做导入、同步和兼容。

## Q-L8：隐私合规如何成为产品能力，而不是免责声明？

### 需要研究

- 单方/双方同意在不同地区和场景的产品提示；
- 会议、家庭、公共空间、医疗和工作场所的差异；
- 录音、ASR、声纹、摘要、Agent 原文读取分别授权；
- 他人请求删除时，原件、Revision、索引、导出和下游引用如何撤回；
- Git 历史、备份和外部 Provider 的不可逆边界如何表达。

### 最小实验

以“开始录音、暂停、云端 ASR、Agent 读取、删除”五个动作制作权限原型，测试用户能否正确预测数据去了哪里，以及撤回后哪些副本仍存在。

## 建议研究顺序

1. 先完成当前真实采集与 ASR Gate；
2. Q-L1 音频价值覆盖率；
3. Q-L5 上层 Review 路径；
4. Q-L4 Evidence 筛选边界；
5. Q-L8 隐私可理解性；
6. Q-L3 跨设备合并；
7. Q-L2 全天候采集；
8. Q-L6 视觉与 Q-L7 硬件。

Q-L2、Q-L6、Q-L7 都是后期 Gate，不得用于阻塞当前 Task 7--12，也不得提前加入当前发布文案。
