# LifeSub V0.2.1 Integrated Native Capture Design

**Status:** Proposed for implementation

**Date:** 2026-08-21

**Milestone decision:** This specification supersedes the earlier split that deferred native capture to V0.2.2. The user explicitly requires native capture in the integrated V0.2.1 deliverable. Project process and roadmap records must point to this decision as the current release boundary.

## 1. Goal

Produce one V0.2.1 desktop build that combines the current four-page UI and Catalog v5 work with verified local ASR, real macOS microphone/system-audio capture, durable evidence publication, and truthful failure behavior. Remove the sidebar import shortcut while retaining import in the Timeline workflow.

The release target is macOS 14+ on Apple Silicon. No desktop path may fall back to demo audio or fabricated transcript text.

## 2. Scope

### Included

- ScreenCaptureKit system-audio capture.
- AVAudioEngine microphone capture.
- Independent source tracks and bounded rolling chunks.
- Permission, device, interruption, sleep/wake, and helper-failure handling.
- Real native SenseVoice/Whisper execution through the existing fenced job lifecycle.
- Persisted Receipt, Revision, Segment, FTS, and live UI events.
- Existing imported-audio ASR flow and retranscription.
- Current Timeline, Dictionary, Notes, Settings, LLM, and quick-input UI.
- Sidebar import removal; Timeline import remains.
- Signed helper and signed/notarization-ready app packaging.

### Excluded

- Diarization and CAM++ identity inference.
- Automatic all-day routing based on communication-app detection.
- Cloud ASR fallback.
- Intel macOS release support.
- UI-process-independent background daemon operation.

### 3.1 Swift capture helper

Create a Swift Package executable named `lifesub-capture-helper` under `src-tauri/native/capture-helper/`.

Responsibilities:

- Query/request Screen Recording and microphone permissions.
- Capture system audio with ScreenCaptureKit without capturing display video.
- Capture the selected microphone with AVAudioEngine.
- Convert each source to a stable working stream for ASR and metering.
- Encode each source independently into bounded audio chunk files using Apple audio frameworks.
- Mark device changes, silence, discontinuities, and dropped buffers.
- Communicate only through the authenticated local protocol.

The helper must not open SQLite, invent session/job identifiers, publish transcript data, or decide that a recording succeeded.

### 3.2 Rust capture coordinator

Replace the production `UnavailableStreamingSource` path with `NativeCaptureCoordinator` while retaining test sources behind `cfg(test)`.

Responsibilities:

- Create a per-launch private socket directory with mode `0700` and socket mode `0600`.
- Generate a cryptographic launch nonce and deliver it only through an inherited anonymous bootstrap pipe.
- Validate peer UID, peer PID, helper executable identity, and the nonce-based protocol handshake.
- Launch and supervise the helper from the signed app bundle.
- Allocate session-scoped staging paths through the anchored Core runtime.
- Validate every helper-reported path stays under the issued staging root.
- Hash, fsync, atomically rename, and commit each sealed chunk.
- Enqueue ASR only after the immutable chunk and Catalog row exist.
- Emit UI events only from committed state.
- Stop, drain, seal, and reconcile on normal stop or failure.

### 3.3 Native ASR executor

Replace `FailClosedEngine` in production with `NativeAsrEngine`.

`NativeAsrEngine` must:

- Load the exact fenced `ExecutionSnapshot`.
- Revalidate the chunk identity and anchored model leases before inference.
- Decode/resample through the existing audio pipeline.
- Run VAD and the selected SenseVoice or Whisper provider.
- Check cancellation and lease ownership between bounded windows.
- Produce a real provider Receipt and source-bound Segment publications.
- Never silently select another model or provider.

`FailClosedEngine` remains available for tests and for builds without a verified native runtime, but it is not selected in the signed V0.2.1 desktop build.

## 4. Capture Protocol

Use a versioned framed protocol over a Unix domain socket. Authentication bootstraps through an inherited anonymous pipe: Rust creates the pipe before spawning, maps the read end to a fixed child FD, closes it everywhere else, and writes the launch nonce through the parent write end after spawn. The nonce must never appear in argv, environment variables, logs, or disk. The helper reads it once, closes the FD, and proves possession in `hello`. Rust also verifies the socket peer UID/PID and that the PID matches the spawned helper process. A failed or replayed handshake terminates the child before accepting audio.

Application messages use this framing:

```text
u32 header_length (big endian)
JSON header (UTF-8, deny unknown fields)
u32 payload_length (big endian)
payload bytes
```

Message types:

- `hello`: protocol version, helper PID, launch nonce, supported sources.
- `permission_state`: microphone and screen-recording states.
- `source_started`: source ID, device ID, sample rate, channel count, host-time anchor.
- `audio_frame`: source, sequence, sample position, host time, discontinuity flags, PCM payload.
- `level`: source RMS/peak values at a bounded rate.
- `chunk_sealed`: source, relative staging path, byte length, duration, source timing range.
- `source_interrupted`: reason and recoverability.
- `source_stopped`: final sequence and timing range.
- `fatal_error`: stable error code and sanitized summary.
- `shutdown_ack`.

Protocol limits are mandatory: maximum header size, maximum payload size, monotonic sequence validation, allowed source names, supported PCM format, and bounded queue depth.

## 5. Audio and Evidence Model

- Microphone and system audio are separate immutable sources.
- Each source rolls chunks independently on a fixed duration boundary and at discontinuities.
- Chunk metadata records source, sample positions, host-time range, sample rate, duration, hash, and integrity state.
- Capture-stage mixing is prohibited.
- The ASR working representation is 16 kHz mono and is derived from the immutable source chunk.
- Live UI ordering uses session-relative monotonic time; UTC is an anchor, not the ordering clock.
- Drift between sources is measured. Excess drift adds a quality warning and never rewrites the original tracks.
- A session becomes `stopped` only after every source enabled for that session has stopped and all accepted chunk files are sealed or explicitly marked failed. Disabled sources do not participate in the stop predicate.

## 6. UI Behavior

- Remove the sidebar `导入音频` action.
- Keep import in Timeline as a deliberate file workflow.
- `开始记录` triggers a real permission/device preflight.
- Status distinguishes microphone permission, screen-recording permission, device readiness, helper state, model readiness, and persistence state.
- A selected capture mode may use microphone only, system audio only, or both; both is the default desktop mode.
- Live transcript rows appear only after corresponding persisted Segment publication.
- Before publication, transient activity is represented as levels/progress, not transcript text.
- Permission denial, missing devices, helper exit, disk pressure, or ASR failure remains visible and actionable.
- Stop never reports “saved” until sealing and Catalog commit complete.

## 7. Failure and Recovery

### Permission and device failures

- Denied/restricted permission prevents the affected source from starting.
- If the user explicitly selected both sources, failure of either source fails start atomically.
- Device disconnect creates a discontinuity, seals the current chunk, and attempts bounded recovery.
- Permission revocation stops the affected source and records a stable error.

### Helper and IPC failures

- Unexpected helper exit seals any coordinator-owned valid chunks and marks incomplete staging files for reconciliation.
- Protocol violation terminates the helper and fails closed.
- Backpressure drops no accepted audio silently; queue exhaustion stops capture with an explicit error.

### Storage failures

- Disk preflight occurs before start and before each new chunk.
- Write/fsync/rename failure stops capture and preserves already committed chunks.
- Startup reconciliation removes unreferenced partial files and marks referenced missing/corrupt chunks.

### ASR failures

- Capture durability is independent of ASR availability.
- A failed ASR job preserves audio and exposes retry/retranscribe.
- Cancellation and ownership fencing remain authoritative.

## 8. Build and Packaging

- Build the Swift helper with SwiftPM for `arm64-apple-macosx`.
- Copy the target-suffixed helper to Tauri `externalBin` input during the native build step.
- Package the helper in `Contents/MacOS` and sign it before signing the outer app.
- Add microphone and screen-recording usage descriptions to the merged Info.plist.
- Keep `LSRequiresCarbon=false` and `NSQuitAlwaysKeepsWindows=false`.
- Build only through the verified Sherpa runtime attestation path.
- Record source worktree, commit, dirty digest, app/helper hashes, version, and test evidence in the release report.

## 9. Verification Strategy

### RED/GREEN automated coverage

- Protocol codec rejects oversized, malformed, replayed, and non-monotonic frames.
- Coordinator validates inherited-pipe nonce, UID, PID, and helper identity; tests prove argv/env/disk do not contain the nonce and reject same-UID impersonation and replay.
- Start is atomic for the requested source set.
- Mic-only, system-only, and dual-source sessions each reach `stopped` using only their enabled-source set.
- Chunk sealing preserves source identity and does not publish before fsync/rename/Catalog commit.
- Helper crash, device interruption, permission revocation, cancellation, lease loss, and disk failure produce durable error states.
- `NativeAsrEngine` maps real provider output into fenced Receipt/Revision/Segment publication.
- Sidebar has no import action; Timeline retains import.

### Native target verification

- Microphone-only, system-only, and dual-source recordings on macOS 14+ Apple Silicon.
- Permission deny, allow, revoke, and Settings round trip.
- Device disconnect/reconnect and sleep/wake.
- Thirty-minute dual-source run with bounded memory and chunk rotation.
- Unique spoken phrase captured from each source, then verified after app restart through search, playback, and export.
- Installed app/helper signature verification and no unexpected dynamic runtime dependency.

### Release gate

- Frontend and Rust suites pass.
- Swift Package tests pass.
- Tier 2 and Tier 3 pass with the verified runtime.
- Real-model Gate passes for the packaged executable.
- Packaged native capture acceptance passes with saved evidence.
- No demo or mock source is reachable from the signed desktop production path.

## 10. Integration Policy

The functional worktree is the integration base. Capabilities from `main` are ported by behavior and tests, not by bulk merge. Each claimed capability must be traced to production wiring and packaged evidence. Existing dirty changes are preserved and reviewed in place.

This document is the authoritative milestone decision for native capture in V0.2.1 and supersedes earlier process/roadmap statements that assigned it to V0.2.2. Those records are updated as part of implementation documentation.

The Task 7 and Task 9 branch refs remain available for patch comparison until the integrated release passes all gates.
